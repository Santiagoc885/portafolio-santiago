## Context

Riwi project (2026): a platform for programming competitions. It remains a working prototype in development, with the main components implemented and ready for further testing and classifier improvements.

## Problem

Programming competitions usually evaluate only the final result, which does not show how the solution was reached or whether AI assistance was involved.

## My responsibility

I worked as a Full Stack Developer, mainly on the backend and on the integration with the classification service:

- Architecture design.
- Recording participant events.
- Database integration.
- Communication between the main backend and the classification service.

## Analysis

The solving process leaves traces in concrete actions: typing, pasting, deleting and running code. Using that process as an additional signal, not only the final code, helps identify possible patterns of AI assistance.

## Solution

Two separate services: one records the process events and the other classifies them to determine whether the behavior is mainly human, AI-generated or AI-assisted.

## Implementation

- **Node.js / Express** receives and records the events from the participant's interaction.
- **FastAPI** exposes the classification service.
- **PostgreSQL** stores users, sessions, problems and events.
- The classifier uses typing, pasting, deleting and running events as variables, along with the frequency and time between events.

## Validation

For event recording, each user action was tested to verify that every event reached the backend and was stored.

Classification was validated with different interaction scenarios, comparing the expected behavior with the classifier's output. That validation also showed which parts needed more data and tuning.

## Result

A working prototype that validates the architecture and the idea of analyzing behavior during problem solving.

There is no formal precision metric for the classifier yet: reporting one would require an evaluation with a labeled dataset.

## Learnings

I learned to design an architecture with separate services and to integrate a traditional backend with a specialized AI service. A reliable classifier does not depend only on the model: it needs a good strategy for collecting, labeling and validating data.

Today I would define the event schema from the start, build a labeled dataset and set metrics such as precision, recall and a confusion matrix before evaluating the classifier.
