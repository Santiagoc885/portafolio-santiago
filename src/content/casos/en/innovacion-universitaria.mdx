## Context

Academic innovation project at Universidad de San Buenaventura Medellín, built by a team of about 10 people under Scrum, with Jira and Git. This is not work experience.

## Problem

The university needed to centralize and digitize how it managed innovation initiatives: registering, browsing, updating and administering information about ideas and opportunities.

## My responsibility

I focused on the backend with Django and PostgreSQL:

- CRUD features with Class-Based Views.
- Business logic.
- Authentication and role-based access control.
- Integration with the API and with stored procedures.

The rest of the team worked on other backend features, the frontend, integration and testing.

## Analysis

The problem was understood from the project requirements and team meetings. Features were broken down into tasks in Jira to track progress.

## Solution

A Django web module to manage innovation initiatives, with role-restricted access, CRUD operations and data logic backed by stored procedures.

## Implementation

- **Class-Based Views** to organize CRUD operations in a structured, reusable way.
- **Stored procedures** to centralize database operations, following the project's technical requirements.
- Authentication and role permissions inside Django.

## Validation

Functional tests for each feature and checks of the integration between backend, database and interface. The project was also validated through demos and reviews against the requirements.

## Result

A working module to manage innovation initiatives, built and presented as part of the academic program.

## Learnings

I learned to work as a team on a shared codebase, structure backend features, integrate an application with PostgreSQL and implement authentication and role permissions.

Today I would define the architecture, automated tests and API documentation from the start, to reduce integration issues and make maintenance easier.
