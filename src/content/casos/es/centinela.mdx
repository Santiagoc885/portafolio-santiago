## Contexto

Proyecto de Riwi (2026) enfocado en servicios cloud y arquitectura sobre Azure. Quedó como un prototipo funcional en desarrollo, centrado en demostrar la arquitectura de detección y el flujo de procesamiento de transacciones.

## Problema

Detectar transacciones potencialmente sospechosas que puedan requerir una revisión adicional.

## Mi responsabilidad

Participé en el desarrollo de la solución, principalmente en los componentes de infraestructura y backend sobre Azure: API, Blob Storage, Service Bus, Azure Functions, Cosmos DB y los mecanismos de identidad y permisos.

## Análisis

La detección se planteó con reglas y un umbral de riesgo: cada transacción recibe un puntaje y las que superan el umbral se marcan como potencialmente sospechosas.

## Solución

Una arquitectura orientada a eventos: la API recibe la transacción y la publica en una cola de Service Bus; una Azure Function procesa el mensaje, aplica la lógica de detección y guarda el resultado en Cosmos DB para su consulta y seguimiento.

## Implementación

- Infraestructura como código con Bicep.
- Comunicación desacoplada mediante Service Bus.
- Acceso entre servicios con Managed Identity y RBAC.
- Red con Virtual Network.
- Configuración centralizada con App Configuration.
- Blob Storage como almacenamiento de apoyo.

## Validación

Se enviaron transacciones de prueba y se comprobó el flujo completo entre los servicios: que cada transacción se recibiera, se procesara y se almacenara correctamente.

## Aprendizajes

Aprendí a diseñar una arquitectura orientada a eventos con servicios administrados de Azure, teniendo en cuenta seguridad, escalabilidad y desacoplamiento entre componentes.

Hoy trabajaría desde el principio con un conjunto de datos de prueba más representativo y con métricas formales de detección, como precisión, recall y falsos positivos.
